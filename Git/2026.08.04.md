# TIL - Git Branch, Merge, Rebase
> 날짜: 2026.08.04

----

## 브랜치(Branch)

브랜치는 독립된 공간에서 기능을 개발하기 위해 사용한다.

### 브랜치 생성

```bash
git branch feature/login
```

### 브랜치 목록 확인

```bash
git branch
```

실행 결과

```bash
PS C:\git\project> git branch

* main
  feature/login
```

`*`이 현재 작업 중인 브랜치이다.

---

### 브랜치 이동

```bash
git switch feature/login
```

또는

```bash
git checkout feature/login
```

실행 결과

```bash
Switched to branch 'feature/login'
```

---

### 브랜치 생성과 동시에 이동

```bash
git switch -c feature/signup
```

또는

```bash
git checkout -b feature/signup
```

---

## 브랜치 이름 규칙

보통 아래처럼 작성한다.

| 브랜치 | 의미 |
|---------|------|
| feature/login | 기능 추가 |
| fix/login-error | 버그 수정 |
| hotfix/security | 긴급 수정 |
| release/v1.0 | 배포 준비 |

---

# Merge

브랜치에서 작업한 내용을 다른 브랜치에 합치는 작업이다.

예를 들어 feature 브랜치에서 작업을 끝냈다면 main으로 이동해서 병합한다.

```bash
git switch main
git merge feature/login
```

---

## Fast-Forward Merge

main에서 작업한 내용이 없으면 그대로 이어 붙여진다.

병합 전

```
A ── B (main)
       \
        C ── D (feature)
```

병합 후

```
A ── B ── C ── D (main)
```

Merge Commit이 생성되지 않는다.

---

## 3-Way Merge

main과 feature 모두 커밋이 있을 때 발생한다.

병합 전

```
A ── B ── C (main)
       \
        D ── E (feature)
```

병합 후

```
A ── B ── C ── M (main)
       \        /
        D ── E
```

M은 Merge Commit이다.

---

### 실제 터미널

```bash
PS C:\git\project> git switch main

Switched to branch 'main'

PS C:\git\project> git merge feature/login

Merge made by the 'ort' strategy.

 login.py | 12 ++++++++++++
 1 file changed, 12 insertions(+)
```

---

# Merge Conflict

같은 파일의 같은 부분을 수정하면 충돌이 발생한다.

터미널

```bash
Auto-merging login.py

CONFLICT (content): Merge conflict in login.py

Automatic merge failed; fix conflicts and then commit the result.
```

git status 확인

```bash
PS C:\git\project> git status

On branch main

You have unmerged paths.

both modified: login.py
```

---

## 충돌 파일

```python
<<<<<<< HEAD
print("main")
=======
print("feature")
>>>>>>> feature/login
```

마커를 지우고 원하는 코드만 남긴다.

예)

```python
print("main")
print("feature")
```

---

### 충돌 해결

```bash
git add login.py
git commit
```

---

# Rebase

Merge 대신 커밋을 한 줄로 정리하고 싶을 때 사용한다.

```bash
git switch feature/login
git rebase main
```

---

## Rebase 전

```
A ── B ── C (main)
       \
        D ── E (feature)
```

## Rebase 후

```
A ── B ── C ── D' ── E'
```

커밋이 새롭게 만들어지면서 이력이 깔끔하게 정리된다.

---

### 실제 터미널

```bash
PS C:\git\project> git rebase main

Successfully rebased and updated refs/heads/feature/login.
```

---

## Rebase 충돌

충돌이 발생하면

```bash
CONFLICT (content): Merge conflict in login.py
```

먼저 파일을 수정한 뒤

```bash
git add login.py
```

계속 진행

```bash
git rebase --continue
```

---

### Rebase 관련 명령어

계속 진행

```bash
git rebase --continue
```

현재 커밋 건너뛰기

```bash
git rebase --skip
```

리베이스 취소

```bash
git rebase --abort
```

---

# Cherry-pick

특정 커밋 하나만 가져올 때 사용한다.

```bash
git cherry-pick a1b2c3d
```

---

# Stash

작업 중인 내용을 잠시 보관한다.

저장

```bash
git stash
```

목록 확인

```bash
git stash list
```

적용 후 삭제

```bash
git stash pop
```

---

# 오늘 배운 점

- 브랜치는 기능별로 작업하기 위해 사용한다.
- Merge는 브랜치를 합치는 기능이다.
- 같은 부분을 수정하면 충돌이 발생할 수 있다.
- 충돌은 내용을 수정한 뒤 `git add` → `git commit`으로 해결한다.
- Rebase는 커밋 이력을 한 줄로 정리할 수 있지만, 협업 중에는 주의해서 사용해야 한다.
- Stash를 사용하면 작업 중인 내용을 임시로 저장할 수 있다.

# 오늘 오류
- branch 이동이 안되고 error라고 뜸. stash로 임시 저장하니 브랜치 이동 함. 다시 복구하니 브랜치 이동 안됨.
## 오류 원인
- commit을 안한 상태로 branch 이동 명령어를 침.

# 오류 해결
- commit을 하고 branch 이동 명령어를 입력해 해결!
