## SQL (데이터베이스에 명령어를 내리는 언어)

### 1. DDL (Data Definition Language) — 데이터 정의어

- **CREATE**: 테이블 생성
- **ALTER**: 테이블 구조 수정
- **DROP**: 테이블 삭제
- **TRUNCATE TABLE 테이블명**: 테이블 구조는 유지하고 데이터만 초기화

### 2. DML (Data Manipulation Language) — 데이터 조작어

- **INSERT**: 추가
- **UPDATE**: 수정
- **DELETE**: 삭제
- **SELECT**: 조회

### 3. DCL (Data Control Language) — 데이터 제어어

- **GRANT**: 권한 부여
- **REVOKE**: 권한 취소

### 트랜잭션 (TCL, Transaction Control Language)

- **COMMIT**: 데이터를 DB에 영구 반영
- **ROLLBACK**: 지금까지 한 변경 작업을 취소하고 되돌림

### 비유로 정리 — 서랍장

| 구분 | 의미 |
|---|---|
| DDL | 서랍장 자체를 제작하거나, 칸수를 바꾸거나, 통째로 부수기 |
| DML | 서랍장은 그대로 두고 서랍 안의 물건을 넣고 빼고 바꾸는 것 |
| DCL | 서랍장을 누가 열어볼 수 있는지 정하기 |
| TCL | 서랍 정리하다가 이대로 확정(COMMIT) 하거나, 방금 한 거 취소 후 원래대로 되돌리기(ROLLBACK) |

## DDL (데이터 정의어) 

### 1. CREATE

**테이블 생성**
```sql
CREATE TABLE 테이블명 (컬럼명 데이터타입 [제약조건] [DEFAULT 값]);
```
[ ]는 선택 항목을 의미

**자동 증감 (Auto Increment)**

- 표준 SQL  INT GENERATED ALWAYS AS IDENTITY 
- PostgreSQL  SERIAL (4byte), BIGSERIAL (8byte) 

### 2. DROP

```sql
DROP TABLE 테이블명;
```

## 제약조건

### 기본키 제약조건 (PRIMARY KEY)

- 중복 허용 X
- 비어있는 값 허용 X (NULL 불가)
- 복합키: PRIMARY KEY (컬럼명, ...)

### NOT NULL

- 빈 값 허용 X
- 필수 입력 항목(컬럼)에 사용

### UNIQUE

- 중복 허용 X
- NULL은 중복 허용됨 (PRIMARY KEY와의 차이점)

### CHECK

- 특정 조건에 해당하는지 검사

### DEFAULT

- 기본값 지정 (직접 지정한 값, 내장 함수 호출, 내장 상수 등)
- 예: 현재 날짜와 시간 → CURRENT_TIMESTAMP

## 외래키 (Foreign Key)

참조 무결성 제약조건이 적용됨

- 부모 테이블에 없는 값을 자식 테이블이 참조할 수 없음
- 부모 테이블의 레코드를 참조하는 자식 레코드가 있으면, 부모 레코드를 함부로 삭제할 수 없음

**ON DELETE 옵션**

| 옵션 | 동작 |
|---|---|
| CASCADE | 부모 레코드가 삭제되면 자식 레코드도 함께 삭제 (연쇄 삭제) |
| SET NULL | 부모 레코드가 삭제되면 자식 레코드의 참조 컬럼 값을 NULL로 교체 |

```sql
CREATE TABLE 테이블명 (
    컬럼명 자료형 [제약조건 등...] REFERENCES 테이블명(컬럼명)
);
```

## 데이터베이스 정규화

데이터 중복과 이상현상을 개선하기 위해 테이블 구조를 단계적으로 개선하는 과정

### 제1정규형 (1NF) — 원자값 유지

- 하나의 컬럼에는 하나의 값만 있어야 함
- 반복되는 값이나 여러 값을 하나의 컬럼에 넣지 않고, 데이터를 원자값으로 분리

 예) 서랍 한 칸에 물건 여러 개 뒤섞어 넣지 않기

### 제2정규형 (2NF)

- 복합키 전체에 종속되도록 테이블 분리

 예) 라벨(기본키) 전체와 관련된 물건만 그 서랍에 두고, 라벨의 절반과만 관련된 물건은 그 절반짜리 라벨을 가진 별도 서랍으로 옮기기

### 제3정규형 (3NF)

- 일반 컬럼끼리의 의존 관계 제거

 예) 서랍 라벨과 직접 관련된 물건만 그 서랍에 두고, 다른 물건을 거쳐서만 연결된 정보는 그 물건 전용 서랍으로 옮기기

## 오늘의 느낀점 / 배운점

- DDL, DML, DCL, TCL을 각각 따로 외우려니 헷갈렸는데 서랍장 비유로 정리하고 나니 각 명령어가 왜 필요한지 구조적으로 이해가 됌.
- PRIMARY KEY는 NOT NULL + UNIQUE를 포함하는 상위 개념이라는 걸 확실히 이해함.
- 외래키의 ON DELETE 옵션(CASCADE, SET NULL)을 배우면서, 단순히 참조만 하는 게 아니라 부모 데이터가 삭제될 때 자식 데이터를 어떻게 처리할지까지 미리 설계해야 한다는 걸 알게 됌.
- 정규화 이론은 어려웠지만 서랍장으로 비유해보니 괜찮았음.
