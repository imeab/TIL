# TypeScript

> 날짜: 2026.10.06

## 제네릭

여러 타입을 하나의 함수나 클래스로 다루면서도 타입 안정성을 지킬 수 있게 해주는 기능이다.
`any`를 쓰면 타입 정보가 사라지지만, 제네릭은 들어온 타입을 그대로 기억한다는 점이 다르다.

### 타입 매개변수 `<T>`

- 관례적으로 Type의 앞글자인 `T`를 쓰고, 여러 개가 필요하면 `T, U, V` 순으로 늘린다.
- 함수를 호출하는 시점에 결정되는 "타입을 담는 변수"라고 생각하면 이해하기 쉽다.

```ts
function identity<T>(value: T): T {
  return value;
}

identity<number>(10); // 타입을 직접 명시
identity("hello");    // T가 string으로 추론됨
```

### 타입 추론

- 호출할 때 `<number>`처럼 타입을 적지 않아도, 전달된 인자를 보고 컴파일러가 `T`를 추론한다.
- 추론 결과가 원하는 타입과 다르거나 애매할 때만 직접 명시하면 된다.

## 제네릭 제약 조건

`extends`로 `T`에 들어올 수 있는 타입의 범위를 제한하는 기능이다.

```ts
interface Lengthwise {
  length: number;
}

function logLength<T extends Lengthwise>(arg: T): T {
  console.log(arg.length);
  return arg;
}

logLength("abc");         // OK
logLength([1, 2, 3]);     // OK
logLength({ length: 5 }); // OK
logLength(10);            // Error: number에는 length가 없음
```

- `T extends Lengthwise`는 "T는 Lengthwise의 하위 타입이어야 한다"는 뜻이다.
- TypeScript는 구조적 타이핑(덕 타이핑)을 사용하기 때문에, Lengthwise를 상속하지 않았더라도 `length: number`만 가지고 있으면 하위 타입으로 인정된다.
- `keyof`와 함께 쓰면 객체에 실제로 있는 키만 받도록 제한할 수 있다.

```ts
function getProp<T, K extends keyof T>(obj: T, key: K) {
  return obj[key];
}

const user = { name: "kim", age: 20 };
getProp(user, "name");  // OK
getProp(user, "email"); // Error: user에 email 키가 없음
```

## 클래스

객체를 만들어내는 틀이다.

### 필드와 생성자

- 필드: 클래스 내부에서 관리하는 변수. TypeScript에서는 타입을 미리 선언해야 한다.
- 생성자(constructor): 객체가 생성될 때 가장 먼저 실행되는 함수로, 필드 값을 초기화한다.

```ts
class User {
  name: string;
  private age: number;

  constructor(name: string, age: number) {
    this.name = name;
    this.age = age;
  }
}
```

생성자 매개변수에 접근 제어자를 붙이면 필드 선언과 초기화를 한 번에 할 수 있다.

```ts
class User {
  constructor(public name: string, private age: number) {}
}
```

### 접근 제어자

내부 데이터를 외부에 어디까지 공개할지 정하는 키워드다.

| 제어자 | 클래스 내부 | 하위 클래스 | 외부 |
| --- | :---: | :---: | :---: |
| public (기본값) | O | O | O |
| protected | O | O | X |
| private | O | X | X |

- `readonly`: 값을 읽을 수만 있고, 선언 시점이나 생성자에서만 초기화할 수 있다.
- TypeScript의 `private`은 컴파일 단계에서만 막아준다. 런타임에서도 완전히 숨기려면 JavaScript의 `#field` 문법을 쓴다.

## 추상 클래스

추상이란 구체적으로 정해지지 않은, 공통적인 것을 뜻한다.

- `class` 앞에 `abstract` 키워드를 붙여 선언한다.
- 직접 `new`로 인스턴스를 만들 수 없고, 상속해서만 사용한다.
- `abstract` 메서드는 구현 없이 형태만 선언하고, 하위 클래스에서 반드시 구현해야 한다.
- 구현이 있는 일반 메서드도 함께 가질 수 있다.

```ts
abstract class Animal {
  abstract makeSound(): void; // 구현 X

  move(): void {              // 구현 O
    console.log("이동 중");
  }
}

class Dog extends Animal {
  makeSound(): void {
    console.log("멍멍");
  }
}

const a = new Animal(); // Error
const d = new Dog();    // OK
```

## 인터페이스

- 객체의 구조(설계도)를 정의하는 타입이다.
- 구현 코드 없이 형태만 선언하기 때문에, 메서드는 모두 추상 메서드처럼 동작한다.
- 클래스는 `implements`로 인터페이스를 구현하며, 여러 개를 동시에 구현할 수 있다.
- 컴파일 후 JavaScript 코드에는 남지 않는다.

```ts
interface Flyable {
  fly(): void;
}

interface Swimmable {
  swim(): void;
}

class Duck implements Flyable, Swimmable {
  fly() { console.log("날기"); }
  swim() { console.log("수영"); }
}
```

### 추상 클래스 vs 인터페이스

| | 추상 클래스 | 인터페이스 |
| --- | --- | --- |
| 구현 코드 | 가질 수 있음 | 가질 수 없음 |
| 필드/생성자 | 가질 수 있음 | 생성자 없음 |
| 다중 사용 | 하나만 상속 (`extends`) | 여러 개 구현 (`implements`) |
| 컴파일 후 | JS 클래스로 남음 | 사라짐 |

공통 로직을 물려줘야 하면 추상 클래스, 형태만 약속하면 되면 인터페이스를 쓰는 편이 자연스럽다.
