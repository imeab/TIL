# Next.js / React

> 날짜: 2026.10.07

## React

UI를 만들기 위한 **라이브러리**다. 화면을 컴포넌트 단위로 나눠서 만들고, 데이터가 바뀌면 필요한 부분만 다시 그린다.

### 빌드 결과와 CSR

React로 만든 앱을 빌드하면 거의 비어 있는 `index.html` 하나와 JS 파일이 나온다.

```html
<body>
  <div id="root"></div>
  <script src="bundle.js"></script>
</body>
```

브라우저가 JS를 받아 실행한 뒤에야 `#root` 안에 화면이 그려진다. 이렇게 브라우저에서 화면을 만드는 방식을 **CSR(Client-Side Rendering)** 이라고 한다.

**장점**

- 처음 로딩이 끝나면 페이지를 이동할 때 서버에서 HTML을 새로 받지 않아서 화면 전환이 빠르다.
- 서버는 데이터(API)만 주고받으면 되므로 서버 부담이 적다.

**단점**

- JS를 다 받고 실행할 때까지 빈 화면이 보여서 초기 로딩이 느릴 수 있다.
- 처음 받은 HTML이 비어 있어서 검색 엔진이 내용을 제대로 수집하지 못할 수 있다. (SEO 불리)

## Next.js

React를 기반으로 만든 **프레임워크**다. 라우팅, 렌더링 방식, 빌드 설정 등을 미리 갖춰두고 있어서 정해진 규칙대로 만들면 된다.

> 라이브러리는 내가 필요할 때 가져다 쓰는 것, 프레임워크는 정해진 틀 안에서 내 코드를 채워 넣는 것

### SSR (Server-Side Rendering)

- **Pre-rendering**: 서버에서 미리 렌더링해서 내용이 채워진 HTML을 보낸다. 그래서 첫 화면이 빨리 보이고 SEO에도 유리하다.
- **Hydration**: 브라우저가 받은 HTML에 JS를 연결해서 클릭 같은 이벤트가 동작하도록 만드는 과정이다. HTML은 이미 그려져 있고, 여기에 "생명을 불어넣는" 단계라고 보면 된다.

빌드 시점에 HTML을 미리 만들어두는 **SSG(Static Site Generation)** 방식도 지원해서, 페이지 성격에 맞게 렌더링 방식을 고를 수 있다.

### 그 외 특징

- **파일 기반 라우팅**: `app` 폴더 안의 폴더 구조가 그대로 URL 경로가 된다. (`app/about/page.tsx` → `/about`)
- **SWC**: JSX/TSX를 JS로 바꾸는 트랜스파일러. Rust로 만들어져서 Babel보다 빠르다.
- **Turbopack**: 여러 파일을 묶어주는 번들러. 역시 Rust로 만들어져 빌드 속도가 빠르다.
