## API (Application Programming Interface)
- 애플리케이션끼리 어떻게 소통할지 정해놓은 명세서
- "이렇게 요청하면 이렇게 응답해줄게"라는 약속

### REST API (Representational State Transfer)
- 핵심 아이디어: 무엇을(자원) 어떻게 할 건지(행위)를 URL과 HTTP 메서드로 나눠서 표현하자
- **자원 (Resource)** — 무엇을 (URL, 명사로 표현. 동사 안 씀)
- **행위 (HTTP 메서드)** — 어떻게 할 건지 (GET/POST/PUT·PATCH/DELETE)

| 메서드 | 의미 | SQL로 치면 |
|---|---|---|
| GET | 조회 | SELECT |
| POST | 생성 | INSERT |
| PUT / PATCH | 수정 | UPDATE |
| DELETE | 삭제 | DELETE |

> REST API는 자원(URL, 명사)과 행위(HTTP 메서드, 동사)를 분리해서 설계하는 방식

## 저장 프로그램 (Stored Program)
DB 서버 안에 직접 로직을 저장해두고 실행하는 것. 세 가지가 있음.

1. **함수 (Function)** — 매개변수를 받아서 반환값을 돌려줌
   - `SELECT` 구문 안에서 바로 사용 가능 (ex. `AVG()`, `SUM()`도 사실 내장 함수)
2. **프로시저 (Procedure)** — `CALL 프로시저명(...)`으로 호출
   - 내부에서 트랜잭션 제어 가능 (`COMMIT`, `ROLLBACK` 직접 실행 가능)
3. **트리거 (Trigger)** — 특정 이벤트(INSERT/UPDATE/DELETE) 발생 시 자동 실행

### 함수 vs 프로시저

| 구분 | 함수 | 프로시저 |
|---|---|---|
| 역할 | 값을 돌려주는 계산 담당 | 작업을 수행하는 실행 담당 |
| 호출 명령어 | `SELECT 함수명();` | `CALL 프로시저명();` |
| 반환값 | 반드시 존재 (RETURNS) | 없음 (INOUT 파라미터로 대체) |
| 트랜잭션 제어 | 불가능 (호출 시 하나의 트랜잭션으로 자동 묶임) | 가능 (COMMIT으로 중간에 락 해제 가능) |
| 실무 활용처 | 프론트엔드와 직접 통신하는 주문/결제 로직 (성공 결과 반환 필요) | 수백만 건 데이터를 쪼개서 정리하는 심야 배치 작업 |

---


- `.table()`이 아니라 `.rpc()`인 이유: 테이블에 직접 접근하는 게 아니라, DB 안에 저장된 함수를 원격으로 호출하는 거라서 (RPC = Remote Procedure Call)
- 함수 안에서 에러가 나면(`RAISE EXCEPTION`) 지금까지 진행된 모든 INSERT가 자동 롤백되고, 파이썬 쪽에서는 `try...except`로 잡을 수 있음

### 스냅샷 패턴
- 주문 시점의 상품명·가격을 `order_items`에 그대로 복사해서 저장
- 이유: 나중에 원본 상품 가격이 바뀌어도 과거 영수증 금액이 같이 바뀌어버리면 안 되니까

### SECURITY DEFINER
- 일반 사용자가 `orders`, `order_items` 테이블에 직접 INSERT 못 하게 권한을 막고, 오직 정해진 함수를 통해서만 주문을 만들 수 있게 강제하는 옵션
- 클라이언트가 보낸 가격을 그대로 믿지 않고, 함수 내부에서 DB의 실제 가격을 다시 조회해서 계산 (가격 조작 방지)

## 대용량 처리는 왜 프로시저로?
- 함수(트랜잭션 하나)로 수만 건을 한 번에 처리하면, 작업이 끝날 때까지 테이블 전체에 락이 걸려서 다른 사용자 요청이 다 막힘
- 프로시저는 `LOOP` 안에서 일정 단위(ex. 5000건)씩 처리하고 그때그때 `COMMIT`을 호출해서 락을 짧게짧게 풀어줄 수 있음
- 그래서 "즉시 응답 + 실패 시 전체 롤백"이 필요한 주문/결제는 함수, "서비스 끊기지 않게 나눠서 처리"해야 하는 배치 작업은 프로시저

## 오늘 느낀점

- 오늘은 REST API랑 함수/프로시저를 같이 배웠다. 
- Supabase SDK로 `.table().select()...` 쓸 때는 사실 뒤에서 REST API(GET/POST 같은 것)가 호출되는 거고 그냥 이렇게 쓰는 거구나 하고 외우기만 했는데 오늘 주문 트랜잭션 예제를 보면서 왜 굳이 함수로 묶어야 하는지가 명확해짐
- 스냅샷 패턴이랑 SECURITY DEFINER 부분을 배웠다. 상품 가격을 바꿔도 예전 영수증이 안바뀌게 만드는 것을 보고 많은 부분을 배웠다.
