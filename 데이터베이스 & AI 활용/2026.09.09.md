## 트랜잭션

### ACID
#### A - 원자성 (Atomicity)
- 모두 성공 또는 모두 실패
- 중간에 하나라도 실패하면 전부 롤백

#### C - 일관성 (Consistency)
- 트랜잭션 전후로 DB의 규칙(제약조건)을 항상 만족해야 함

#### I - 격리성 (Isolation)
- 동시에 실행되는 트랜잭션들이 서로 간섭하지 않음 (동시성 문제 방지)
- `SELECT ... FOR UPDATE`

#### D - 지속성 (Durability)
- COMMIT 하면 DB에 영구 반영, 이후 서버가 꺼져도 유지됨

### BEGIN / COMMIT / ROLLBACK
- `BEGIN;` → 트랜잭션 시작
- `COMMIT;` → 트랜잭션 종료 (DB에 영구 반영)
- `ROLLBACK;` → 트랜잭션 취소, **COMMIT 전에만 가능**

> SQL 한 줄만 실행할 땐 자동으로 BEGIN~COMMIT 처리됨 (autocommit)
> 여러 SQL을 하나의 단위로 묶어야 할 때 (ex. 계좌이체) 명시적으로 사용

## SDK

- API를 직접 호출하지 않고, 함수 형태로 쉽게 쓸 수 있게 감싸놓은 도구 모음
- Supabase SDK는 내부적으로 REST API를 호출함

### Supabase 연동

```python
import os
from supabase import create_client

url = os.getenv("SUPABASE_URL")
key = os.getenv("SUPABASE_PUBLISHABLE_KEY")

# supabase 클라이언트 객체 생성
supabase = create_client(url, key)
```
- `.env`에 URL, KEY를 저장해두고 `os.getenv()`로 불러와서 사용
- 코드에 키를 직접 적으면 GitHub 등에 노출될 위험이 있어서 환경변수로 분리

### 1. INSERT
테이블에 새 데이터 추가. 컬럼명을 key로 하는 딕셔너리 형태로 전달. 마지막에 `.execute()`를 붙여야 실제로 요청이 전송됨.

```python
response = supabase.table("users").insert({"email": "user03@test.org"}).execute()
```

### 2. SELECT
`select("*")`는 전체 컬럼, `select("id, title")`처럼 지정하면 해당 컬럼만 조회. 결과는 `response.data`에 저장됨.

```python
response = (
    supabase.table("users")
    .select("*")
    .ilike("email", "user02%")
    .single()
    .execute()
)

print(response.data)
```

#### 조건 필터링

| 메서드 | 역할 | 예시 |
|---|---|---|
| eq | 값이 같은 행만 필터 | `.eq("id", 1)` |
| order | 정렬 | `.order("created_at")` |
| limit | 개수 제한 | `.limit(10)` |

#### single vs maybe_single

| | 반환 | 결과 0개 | 결과 1개 | 결과 2개 이상 |
|---|---|---|---|---|
| `.single()` | 딕셔너리 | 에러 | 정상 반환 | 에러 |
| `.maybe_single()` | 딕셔너리 or None | None (에러 아님) | 정상 반환 | 에러 |

→ 무조건 1개 있어야 하는 조회(PK 등)는 `.single()`, 없을 수도 있는 조회(이메일 검색 등)는 `.maybe_single()`

### 3. UPDATE
```python
response = (
    supabase.table("documents")
    .update({"title": "첫 번째 문서(수정)"})
    .eq("id", "31a438ee-02fe-4612-863b-2fde02b595fd")
    .execute()
)
```

### 4. DELETE
```python
response = (
    supabase.table("users")
    .delete()
    .eq("id", "cf2e696a-36c4-462a-86fb-af4a25dc970c")
    .execute()
)
```

## Authentication
- 사용자의 가입, 로그인, 세션 관리를 대신 처리해주는 Supabase 기능
- 비밀번호 암호화, 토큰 발급, 이메일 인증 등을 직접 구현할 필요 없음
- `supabase.auth` : 인증(로그인) / 인가(접근 제한) 관련 메서드를 가진 객체

### 회원가입
```python
response = supabase.auth.sign_up({
    "email": "user01@test.org",
    "password": "password1234",
    "phone": "01010001000"
})
```

### 로그인
```python
response = supabase.auth.sign_in_with_password({
    "email": "user01@test.org",
    "password": "password1234"
})
```
- 로그인 : 사용자에 대한 식별 정보(세션/토큰)를 유지
- 로그아웃 : 식별 정보를 삭제


## LangChain
- AI 모델(OpenAI, Claude 등) API만으로는 대화 기억, 문서 검색, 외부 도구 사용 같은 기능을 직접 구현해야 함
- LangChain은 이런 기능들을 미리 조립해둔 프레임워크

```python
prompt_template = ChatPromptTemplate.from_messages([
    ("system", "당신은 컴퓨터 기초 개념을 일상적인 사물에 빗대어 설명하는 교육 전문가입니다. 2문장 이내로 친절하게 설명하세요."),
    ("user", "{user_question}")
])
```
- `from_messages()`는 리스트(`[ ]`)를 받음
- `"{user_question}"`처럼 문자열 안에 중괄호로 감싸면 나중에 값이 채워질 placeholder가 됨
- `{"user_question"}`처럼 따옴표 밖에 중괄호를 쓰면 set으로 인식돼서 에러남 → 실수 주의

### 오늘 겪은 에러
- `Invalid login credentials` : 이메일/비밀번호 불일치, 또는 이메일 인증 미완료
- `User already registered` : 이미 가입된 이메일로 재가입 시도
- 개발 단계에서는 Authentication → Settings에서 이메일 confirm 옵션을 꺼두면 편함
